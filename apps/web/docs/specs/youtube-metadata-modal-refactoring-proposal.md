# YoutubeMetadataModal 리팩토링 제안서

**작성일자:** 2026-04-13
**대상 파일:** `src/fsd/widgets/clip-display/ui/_component/YoutubeMetadataModal.tsx`

## 1. 개요
현재 `YoutubeMetadataModal.tsx` 컴포넌트는 생성된 유튜브 클립(Clip)의 메타데이터(제목, 설명, 해시태그)를 보여주고 복사하는 기능이 잘 구현되어 있습니다. 하지만 파일의 길이(약 338줄)가 다소 길며, 여러 관심사(프레젠테이션, 비즈니스 로직, 복잡한 스타일링)가 섞여 있어 유지보수성과 가독성을 저하시킬 수 있습니다.

이에 따라 **기존의 로직과 기능은 전혀 변경하지 않되**, 더욱 모던하고 깔끔한 아키텍처 구성을 위한 단계별 리팩토링을 제안합니다.

## 2. 주요 개선 제안

### A. 로컬 UI 컴포넌트 파일 분리 (관심사 분리)
파일 상단에 위치한 `CopyButton`과 `CharacterCountBar`는 상태를 거의 갖지 않거나 독립적인 역할을 하는 프레젠테이션 컴포넌트입니다.
- **제안:** 해당 컴포넌트들을 FSD 아키텍처에 맞추어 `shared/ui/molecules` 위치나, 현재 폴더의 하위 `_component` 뎁스에 각각 독립된 파일(`CopyButton.tsx`, `CharacterCountBar.tsx`)로 분리합니다.
- **기대 효과:** 메인 모달 파일의 라인 수가 크게 줄어들고 JSX의 핵심 뼈대인 뷰(View) 구조가 한눈에 파악됩니다.

### B. 비즈니스 로직의 커스텀 훅(Custom Hook) 분리
복사 상태 피드백을 위한 `copiedField` 관리와 클립보스 복사에 사용되는 `handleCopyMetadata`, 전체 복사를 위한 `handleCopyAllMetadata` 함수 등은 뷰 렌더링과는 무관한 비즈니스 로직입니다.
- **제안:** 사용자 인터랙션과 상태 처리 비즈니스 로직을 하나로 묶어 `useMetadataClipboard(clip)` 같은 커스텀 훅으로 추출합니다.
- **기대 효과:** UI 컴포넌트는 순수 렌더링에만 집중할 수 있으며, 클립보드 피드백 로직을 격리하여 관리 및 단위 테스트(Unit Test) 하기가 유리해집니다.

### C. 복잡한 Tailwind CSS 스타일링 상수화
현재 컴포넌트에 적용된 Tailwind CSS 클래스들은 화면 전환, 그라디언트, 호버 효과 조합 등으로 인해 매우 깁니다. 
- **제안:** `cva` (Class Variance Authority) 라이브러리를 활용하거나 파일 외부(또는 상단)에 `const STYLES = { container: "...", button: "..." }` 형태의 상수로 묶어서 사용합니다.
- **기대 효과:** JSX 태그 부분이 훨씬 간결해지며 컴포넌트 트리 형태를 파악하는 것을 가리는 시각적 노이즈를 제거할 수 있습니다.

### D. 하드코딩된 값(Magic Number & String)들의 상수화
- **제안:** 복사 후 "Copied!" 문구가 유지되는 시간의 `setTimeout` 지연값 `2000`(ms)이나, 탭 밸류 `"Title"`, `"Description"`, 유니온 타입 키워드 등을 의미 있는 상수로 추출합니다.
  - 예: `const COPY_FEEDBACK_DELAY_MS = 2000;`
- **기대 효과:** 추후 기획 변경으로 시각적 피드백 유지 시간을 2초에서 3초로 변경해야 할 때, 복잡한 로직 내부를 찾아다니지 않고 상단 상수만 변경하여 버그 없이 유지보수할 수 있습니다.

### E. 파생 데이터 및 포맷팅 로직 유틸리티화
`handleCopyAllMetadata` 내부에서 전체 메타데이터를 하나의 문자열로 취합(`join`)하고, 유효하지 않은 데이터를 거르는(`filter(Boolean)`) 텍스트 병합 과정은 순수 함수로 처리될 수 있습니다.
- **제안:** 이를 `formatAllMetadataForCopy(clip)` 등의 유틸리티 함수로 외부에 분리합니다.
- **기대 효과:** 로직 분리로 인해 컴포넌트 내에서의 복잡한 데이터 조작이 사라지고 텍스트 병합 결과에 대한 단위 테스트가 쉬워집니다.

## 3. 결론
이러한 모듈 분리(컴포넌트 단위 조각화, 상태 및 비즈니스 로직 캡슐화, 상수 맵핑) 리팩토링은 기존 사용자 경험(UX)이나 로직 흐름에 그 어떤 변경도 주지 않으면서 **현재 및 미래의 클린 코드 기준(2026년 모범 사례)에 완벽히 부합**하도록 만들어 줄 것입니다.
