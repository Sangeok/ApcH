# plans

`PROJECT_BOARD.md`의 항목 하나당 계획서 하나. 담당 에이전트가 **코드를 고치기 전에** 쓰고,
사용자가 읽고 승인한 뒤에야 구현이 시작된다.

## 파일명

`<항목ID>.md` — 보드의 항목ID를 그대로 쓴다 (`BUG-05.md`, `FEAT-01.md`).

에이전트가 보드를 읽고 경로를 **계산**할 수 있어야 하므로 날짜나 제목을 붙이지 않는다.

## 절 구조

`template.md`가 단일 출처다. 에이전트는 계획서를 쓰기 전에 그 파일을 읽는다.

## 수명

`active/`·`completed/` 분리를 두지 않는다. 항목의 상태는 **보드에만** 있다 —
파일 위치가 상태를 나타내면 둘이 어긋날 수 있고, 에이전트에게는 파일을 옮길 도구가 없다
(`Bash`는 읽기·검증 전용이고 삭제 도구가 없다).

`보류` 후 계획을 다시 쓸 때는 같은 파일을 **덮어쓴다.** 막힌 이유는 보드의 `결과:` 줄에 남으므로
기록이 두 곳에 필요하지 않다.

## 같은 경로를 쓰던 이전 문서들

`docs/proposals/completed/` 아래 제안서들이 `docs/plans/2026-08-01-monorepo-conversion.md` 같은
경로를 인용한다. 그것들은 모노레포 전환기에 쓰인 **다른 종류의 계획서**이고 지금은 삭제됐다.
날짜가 앞에 붙은 파일명(`YYYY-MM-DD-*.md`)이면 그쪽, 항목ID면(`BUG-05.md`) 이쪽이다.

그 인용들은 완료된 기록이라 고치지 않는다.
