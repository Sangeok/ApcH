# agents — 행위자 보고서

`PROJECT_BOARD.md`는 **상태**(무엇이 어느 단계인가)를 담고, 이 폴더는 **활동**(누가 무엇을 했나)을 담는다.
보드 행의 `근거`·`결과`는 150자 이내 요약이고, 상세는 전부 여기로 온다.

## 경로

```
docs/agents/<행위자>/<항목ID>.md   항목에 묶이는 작업
docs/agents/<행위자>/<고정명>.md   항목에 묶이지 않는 작업
```

에이전트가 보드를 읽고 **경로를 계산**할 수 있어야 하므로 날짜나 제목을 파일명에 붙이지 않는다
(`docs/plans/README.md:10`과 같은 원칙).

## 행위자 여섯

| 행위자 | 담는 것 |
| --- | --- |
| `main-loop` | 계획서 검증 라운드, 인수 기록, **게이트 결정**(사용자가 게이트를 열지만 기록자는 메인 루프다) |
| `admin-dev` | `apps/admin` 구현 보고 |
| `web-dev` | `apps/web` 구현 보고 |
| `backend-dev` | `apps/backend` 구현 보고 |
| `doc-auditor` | 감사 보고 (쓰기 도구가 없어 메인 루프가 저장한다) |
| `feature-scout` | 정찰 보고 (같음) |

**`pm`은 폴더를 갖지 않는다.** `.claude/agents/pm.md`가 백로그와 보드 외 새 파일 생성을 금지하며,
pm의 산출인 선정 근거는 보드 `근거` 한 줄로 충분하다.

**`plan-verifier`도 폴더를 갖지 않는다.** 보고는 디스패치의 최종 메시지로 반환되고, 메인 루프가
`main-loop/<항목ID>.md`의 검증 라운드 기록에 담는다 — 검증 기록의 집이 이미 거기이기 때문이다.

**`main-loop`은 `.claude/agents/*.md` 정의 파일이 없다** — 서브에이전트가 아니라 디스패처이기 때문이다.
`pm.md`의 표 관리 규칙("정의 파일이 없는 에이전트는 적지 않는다")을 이 폴더에 적용해 지우지 말 것. 의도된 예외다.

## 고정명 — 닫힌 목록

항목에 묶이지 않는 작업의 파일명은 발명하지 않는다. 현재 둘뿐이다.

| 행위자 | 고정명 | 담는 것 |
| --- | --- | --- |
| `doc-auditor` | `감사기록.md` | 감사 1회 = 절 1개. **소득 0건도 기록한다** — "언제 돌았고 결과가 0건"이 이력이다 |
| `feature-scout` | `정찰기록.md` | 정찰 1회 = 절 1개. 직전 절이 다음 정찰의 중복 제안 배제 입력이다 |

새 고정명은 해당 부류의 작업이 실제로 생길 때 이 표에 행을 더해 늘린다. 미리 만들지 않는다.

## append-only

**보고서는 절대 덮어쓰지 않는다.** 새 내용은 절을 더해 이어 붙인다.

`docs/plans/`의 계획서가 재작성 시 덮어쓰는 것과 반대인데, 성격이 다르기 때문이다 —
계획서는 **현재 계약**이라 하나만 유효하고, 보고서는 **누적 기록**이라 전부 유효하다.
보류 후 재구현해도 첫 시도의 보고를 지우지 않는다.

## 폴더는 미리 만들지 않는다

git이 빈 디렉터리를 추적하지 못한다. 각 폴더는 그 행위자의 **첫 보고서가 만든다.**
아직 돌지 않은 행위자의 폴더는 자연히 없다 — 그 부재 자체가 "아직 실행된 적 없음"이라는 정보다.

## 감사 대상이 아니다

`doc-auditor`는 이 폴더를 검사하지 않는다. 보고서는 **작성 시점의 상태**를 담으므로
`파일:줄` 인용이 시간이 지나면 낡는 것이 정상이다(`docs/**/completed/**`와 같은 이유).
