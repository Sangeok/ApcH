## 착수 전 실측 — 백로그 진단 둘을 교정했다

백로그 인용은 전부 현재도 정확했다(`analytics-contract.ts:30`, `metadata.ts:48`·`:63`,
`admin/queries.ts:74`·`:90`, `web/route.ts:15`). 그러나 **요구 ③과 area가 틀렸다**:

- **`apps/admin/.../queries.test.mjs`는 대상이 아니다.** 그 파일 `:6`의 `ANALYTICS_EVENT_NAMES`는
  계약 사본이 아니라 `mock.module("@repo/db", …)`로 주입하는 **세 개짜리 목 픽스처**다
  (`landing_view`·`dashboard_viewed`·`upload_prepare_failed`). 계약은 31개라 애초에 일치시킬
  의도가 없고, 이름을 지워도 깨지지 않는다. 백로그의 "하드코딩 사본이 계약과 어긋나 깨진다"가
  사실과 다르다.
- **백로그가 못 본 곳이 둘 있다.** (a) `apps/web/src/fsd/shared/analytics/event-catalog.test.mjs:27`이
  이름 목록을 전수 순회하며 metadata 정의 존재를 단언한다 — 이번 변경의 **실제 안전망**이다.
  (b) `apps/web/src/fsd/shared/analytics/lib/metadata.test.mjs:46-48` 주석이 이 이름을 근거로
  든다 — 지우면 유령 주석이 된다.

결과적으로 「고칠 파일」은 백로그 area와 다르다: `analytics-contract.ts` · `metadata.ts` ·
`metadata.test.mjs` 셋이고, admin 파일은 빠진다.
