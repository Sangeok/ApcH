재실행에서 **돌연변이 대조군(원본)이 실패**했다. 원인은 내가 D3으로 넣은 명세였다 — "차이가 정확히 0.05초면 FRESH"는 부동소수점 때문에 구현과 모순된다:

```
|10.05 - 10| = 0.05000000000000071   > 0.05 ? true   ← STALE이 된다
|0.05  -  0| = 0.05                  > 0.05 ? false  ← 0 기준에서만 정확
```

즉 M8은 명세 구멍이 아니라 **도달 가능한 입력으로 구별되지 않는 등가 변이**였다. 이 저장소에는 같은 판정의 선례가 있다(`boundary-snap.test.mjs`의 `roundTenth` — `apps/web/CLAUDE.md` 테스트 표). 계획서의 그 줄을 "의도적으로 테스트하지 않는다 + 왜"로 교체했다.

정정 후 돌연변이 재실행: 대조군 통과, **M7 사멸**(방향 케이스가 잡는다), M8은 문서화된 등가 변이로 생존, 나머지 8종 전부 사멸.
