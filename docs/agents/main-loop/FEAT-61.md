# FEAT-61 — 메인 루프 기록

## 게이트① (2026-10-14)

소유자가 2026-10-13 세션에서 「`/dashboard/settings`의 caption position을 top/middle/bottom 버튼이 아니라 preview에서
마우스로 조정할 수 없나」를 물었다. 메인 루프가 위치의 흐름(미리보기 → 저장 JSON → Inngest → `resolve_caption_style`의
alignment + marginv)을 추적해 가능하다고 답하고, 가로는 빼자고 권했다. 근거는 백엔드가 쓰는 Anton-Regular.ttf의 실제 글자
폭 계산 — 기본 설정(영어 5단어·122)에서 한 줄이 프레임 폭의 77%(833/1080px)이고, 같은 5단어라도 큐마다 44~77% 이상으로
달라 설정 화면의 샘플 한 줄로는 실제 큐가 화면 안에 남는지 약속할 수 없다. 소유자가 「세로로만 하자」로 정했다.

- 백로그 등재: FEAT-61(backend, 받는 쪽 먼저) · FEAT-62(web) 두 항목. 소유자 직접 지정이라 pm 대신 메인 루프가 보드에
  `승인대기`로 올렸다(FEAT-60 전례) — `e2c09ab`.
- 게이트①: 소유자가 「둘 다 계획지시로 진행」으로 열었다 — `61edf2c`.
- **공유 계약(메인 루프 고정)**: 두 계획을 병행으로 쓰게 하려고 디스패치 브리핑에 같은 계약을 실었다 — 키 `marginV`(정수
  또는 null, 없으면 null), `position`이 기준 가장자리(top=위에서, bottom=아래에서, middle=무시), 범위 0~960(PlayResY/2),
  잘못된 값은 상수표(200/260) 폴백. 디스패치 전에 로컬 ffmpeg(libass)로 계약을 실측했다 — alignment 5는 marginV 0과 900의
  렌더가 같고(`top=933 bottom=1007`), 허용 최대 스타일(크기 200·8단어·대문자, 3줄 500px)이 marginV 960에서 top
  `1022~1522`·bottom `422~922`로 프레임 안이다. marginV는 글자 잉크가 아니라 줄 상자 끝까지다(크기 122에서 잉크가 위 34px·
  아래 14px 안쪽).
