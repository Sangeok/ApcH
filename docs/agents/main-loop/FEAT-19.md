# FEAT-19 — 배포 확인 원장 도입 (메인 루프 직접 구현)

## 발주 경위 (2026-08-24)

사용자가 "파이프라인에 보완·확장이 아니라 신규로 추가할 것"의 파악을 지시했고, 메인 루프의
제안 넷 중 ①(배포 후 확인 단계)을 승인했다("좋다 진행하자"). 게이트①② 미경유 —
루트 문서 작업은 담당 dev가 없고, FEAT-12 전례(소유자 발주 → 메인 루프 직접 구현 → 보드 기록)를
따랐다. 코드 무변경.

## 발주 근거가 된 관측

`못 덮` grep 실측: 계획서 13건 + 구현 보고 6건 + 제안서 1건이 「배포 후 수동 확인」 목록을
선언했으나, 그 마감 기록은 저장소 전체에서 0건. 파이프라인의 검증 엄밀함(검증 라운드·돌연변이
검사·실물 렌더)이 merge 시점에서 끊기고, 실물 화면 확인은 원장 없는 부채로만 쌓이고 있었다.

## 설계 결정

1. **원장 위치는 `docs/` 루트.** `docs/agents/`는 활동 기록(append-only)이고 원장은 상태
   문서(체크박스 갱신형)라 규약이 충돌한다 — `docs/agents/README.md`의 상태/활동 구분 자체가
   근거다. 보드에 넣지 않은 이유는 FEAT-12 감압 취지(보드는 요약만).
2. **마감은 증거 3종으로만** — 확인(실물 관측)·대체(후속 항목의 화면 교체·재선언)·이관(백로그).
   "확인했다" 한 줄 금지는 `verification-paths.md` 증거 형식과 같은 원칙이다.
3. **백필 16건**: FEAT-18·17·16·15·14·13·12·10·09·08·07·06·04·03·02·BUG-05.
   원천 우선순위는 구현 보고 > 보드 `결과` > 계획서. BUG-05는 보드 행이 없으나 구현 커밋
   `1a38e1e`(2026-08-05)와 계획서의 수동 검증 시나리오가 실재해 포함했다.
   BUG-06은 제외 — 선언(카피↔로직 사람 대조)이 구현 시점에 닫히는 성격이다.
4. **백필에서 닫은 것**: FEAT-03·04의 명령 경로(fetch·POST·토스트)는
   `docs/proposals/active/remote-agent-pipeline-generalization.md` Verification Results ③
   (2026-08-15, 버튼→토스트→코멘트→답글 전 구간 관측)으로 확인 마감. 대체 마감은 FEAT-06 전부,
   FEAT-04 TeamZone·세리프 폴백, FEAT-07 반응형(5→7책상), FEAT-03 카드 렌더.
   **FEAT-08 도장 실사용은 닫지 않았다** — FEAT-09 근거의 "도장으로 열 예정(첫 실측 겸)"은
   예정 기록일 뿐 실측 결과 기록을 못 찾았다. 소유자가 실사용 기억으로 닫을 수 있다.
5. **보드 `agent: main-loop` 안전성 확인**: 대시보드 `known-agents.ts:48` `identityFor`가
   roster 밖 id를 `{handle: id, role: "에이전트"}`로 폴백 렌더한다 — 페이지가 깨지지 않는다.
   책상은 roster 고정 7이라 새 책상도 생기지 않는다.
