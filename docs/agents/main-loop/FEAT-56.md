## 라운드 1 — 일곱 경로 전수 (소득 2건)

하니스: `scratchpad/feat56/`.

**경로 1.** 인용 **24건**을 (파일, 줄, 기대 부분문자열)로 기계 대조 — **불일치 0**.
수 주장도 확인했다: `ClipDraftCard` 전문의 `playUrl` 출현 = `[38, 54]` 정확히 둘,
`readyPlayUrl` = `[100, 228, 454]`, test describe = `[13, 55, 96]`, `it` 총 **14**.

「현재 동작」이 describe를 `:55`·`:96`으로, 「구현 스케치」가 삭제 범위를 `:53-92`·`:94-117`로
적어 **달라 보이지만 모순이 아니다** — `:53`·`:94`는 각 describe의 선행 주석이고, 삭제 범위가
그것을 포함하는 쪽이 옳다(안 그러면 고아 주석이 남는다).

**경로 3.** before **14개**(펜스 블록 11 + 인라인 3)가 각각 트리에 **정확히 1회** 출현.
전부 손 개입 없이 after로 치환됐다.

**경로 2 — 실제 게이트 실행.** 치환본을 트리에 적용해 게이트 둘을 직접 돌렸다.

| 게이트 | 결과 |
| --- | --- |
| `npm run check -w apps/web` | **EXIT 0 · `✔ No ESLint warnings or errors`** — 백로그 요구 ②a(경고 0) 충족. `playUrl` 경고 소멸 |
| `npm test -w apps/web` | **tests 170 / suites 40 / fail 0** — 계획서 예측과 **정확히** 일치 |

기대값 170/40의 전제도 따로 검산했다. `describe` 총수 **42 == suites 42**(러너가 describe를
suite로 센다), `it` 172 + `test(` 6(`middleware.test.mjs` 3 · `event-catalog.test.mjs` 3) = **178**.
제거 구간의 `it`은 **평범한 8개, 루프 0** — 따라서 178−8=170, 42−2=40이 산술로 선다.

**경로 8 — 실물 렌더.** 계획서의 before/after JSX를 esbuild로 트랜스파일해
`renderToStaticMarkup`으로 실제 렌더했다(React 19).

| 입력 | 마크업 동일 |
| --- | --- |
| `sample=true` · English | **true** |
| `sample=true` · Korean | **true** |
| `sample=false` · English | false |
| `sample=false` · Korean | false |

**앞 둘이 이 항목의 「동작 무변경」 증명이고, 뒤 둘이 「지운 것이 실재했다」는 증명이다** —
빈 분기를 지운 게 아니라 실제로 다른 마크업을 내던 분기를 지웠다.

**경로 7 — 음성 시험(등가 증명).** 계획이 기대는 「`previewCaptionCues`는 `sample=true`에서
항등」을 `git show HEAD:`의 **원본 함수**로 실행 검증했다. 언어 English·Korean·Japanese·빈문자열
넷 모두 `out === cues`(동일 객체) — `buildCaptionCues` 직접 호출과 동치다.

반대 방향도 봤다: 라이브 경로의 실제 입력(**영어 전사 + Korean 업로드**)에서
`sample=false`는 첫 큐를 `"Style your captions"` → `"지금 자막 스타일을"`로 **실제 치환한다.**
지우는 것이 no-op이 아니었다.

> 첫 시도는 한국어 입력에 한국어 치환을 걸어 「치환이 안 일어난다」는 거짓 음성을 냈다.
> 하니스 결함이었고, 입력을 라이브 경로의 실제 모양으로 바꿔 다시 돌렸다.

**경로 5 — 돌연변이 검사.** 삭제 항목의 고유 위험은 「남은 명세가 비는 것」이다.
남은 4 export(`SAMPLE_CAPTION_CLIP_END`·`sampleCaptionWords`·`firstCueText`·`firstSampleCueText`)에
돌연변이 4종을 심었다.

| 돌연변이 | 남은 6케이스 |
| --- | --- |
| M1 `firstSampleCueText`가 항상 빈 문자열 | 사멸 |
| M2 `sampleCaptionWords`가 언어 무시 | 사멸 |
| M3 단어 `start: i → i+1` | **생존** |
| M4 단어 `end: i+0.9 → i+0.4` | **생존** |

M3·M4 생존이 이 삭제 탓인지 가리려고 **삭제 전 원본 14케이스**로 같은 돌연변이를
전체 스위트에 대고 다시 돌렸다 — **둘 다 똑같이 생존**한다.
**타이밍 구멍은 원래 있던 것이고 이 항목이 만든 게 아니다. 삭제로 잃은 커버리지 0.**

**경로 4 — 전칭 여집합.** 적용본에서 `previewCaptionCues`·`koreanSampleCues`·`playUrl={readyPlayUrl}`
전역 잔존 **0건**, `CaptionStyleInput`은 정의 1줄만 남음(계획대로). 변경 파일은 **정확히 11개**로
「여기 없는 파일은 고치지 않는다」와 일치. `readyPlayUrl`이 죽지 않았다는 주장은 경고 0 통과가
기계로 확인한다(죽었으면 미사용 경고가 난다).

### 소득 2건

| # | 결함 | 근거 | 성격 |
| --- | --- | --- | --- |
| 1 | 머리말이 「보드 area에 `features/caption-style`가 없다」고 단언 — **거짓** | 게이트① 때 메인 루프가 백로그 원본에 더해뒀다. 실제로 빠진 것은 관측 6의 `caption-style-schema.ts` 하나뿐 | 문서 위생 |
| 2 | 「`sample=false` 기반 죽은 코드(A+B+C)**만** 제거」라는 전칭이 **넷째를 빠뜨린다** | `CaptionPreviewPlayer.tsx:125` `props.sample === true ? firstCueText(cues) : activeText`의 else 갈래도 `sample=false` 기반이고 도달 불가로 **남는다** | 문서 위생(구현 지시는 명시적이라 안 바뀜) |

**결함 2가 이 항목의 존재 이유와 같은 모양이다** — FEAT-56은 FEAT-52의 계획서가
「삭제로 죽는 것」을 열거하지 않아 생겼는데, 그 계획서가 다시 열거를 하나 빠뜨렸다.
다만 `:125`를 남기는 것 자체는 옳다 — 그것은 **유지하기로 한 `playUrl` machinery와의 접합부**이고,
지우려면 (B)를 통째로 해야 한다. 그래서 전칭을 고쳐 「셋을 제거하고 하나는 (B)에 딸려 남긴다」로
명시하고, 후속 정리 후보에 `:125`를 `playUrl` machinery와 **한 덩어리**로 묶었다.

**적용한 편집(일괄 1회)**: 머리말의 area 서술 정정 · 「대안」⑤에 `sample` 의존 코드 여집합
전수(넷)와 `:125`를 남기는 이유 추가.
