### 라운드 1 소득 — 구현 영향 0 / 문서 위생 2

구현을 틀리게 하는 결함은 나오지 않았다. 계획서에 반영한 것은 둘이다.

1. **전칭 주장이 실측보다 좁았다.** 「render 경로 변화」가 *"'moment 없음 + request 있음'에서만
   None→request로 바뀐다"*고 적었는데, 144조합 대조 결과 실제 변화 조건은 (a) moment가 **없을**
   때가 아니라 **dict가 아닐** 때 전부(문자열·리스트 포함)이고, (b) `render`만이 아니라
   **`auto`를 제외한 모든 모드**다. `analyze`는 클립 루프 밖이라 현재 도달 불가이므로 관측
   가능한 변화는 render뿐 — 결론은 같지만 근거가 달랐다. 실측 수치와 함께 정정하고,
   `mode` 가드 제거의 설계 귀결(앞으로 추가되는 모드는 자동으로 폴백을 받는다)을 명시했다.
2. **검증 게이트에 기대값이 없었다.** "전체 스위트는 그대로 녹색"이라고만 적혀 있어 인수 때
   기계적 판정이 안 된다. 실측 기준선 `Ran 117` → 구현 후 기대 `Ran 113`(이 모듈 12→8)을
   박고, 다른 숫자가 나오면 멈추라는 지시를 더했다. `PYTHONUTF8=1`도 게이트 명령에 넣었다.
