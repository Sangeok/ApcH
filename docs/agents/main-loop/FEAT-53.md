# FEAT-53 — `ClipDraft.captionStyle` 컬럼 제거 (메인 루프 기록)

## 게이트① (2026-09-17)

소유자 직접 발주 — 세션 지시 "Feat 53 진행". 미결 0건을 확인하고 보드에 `계획지시`로 올려
커밋·푸시한 뒤, **계획서도 내가 썼다** — `packages/db`는 dev 로스터 쓰기 범위 밖이라 담당이
main-loop다(FEAT-19·FEAT-26·FEAT-38·FEAT-47 전례).

**그래서 이 항목은 구조적으로 약하다.** 계획서 저자와 검증 라운드 수행자가 같다. 내 라운드는
평소보다 더 회상에 가깝고, `plan-verifier`의 독립 패스가 평소보다 더 무겁다. 이 사실을 여기
적어 둔다.

선행 조사로 FEAT-47(같은 스키마 마이그레이션, main-loop)을 먼저 읽었다. 그 계획서가 남긴 것이
이번에 그대로 쓰였다 — 마이그레이션 히스토리 드리프트(`ClipDraft` 생성 마이그레이션 부재),
`migrate dev` 금지, `packages/db`에서 Prisma CLI가 루트 `.env`를 못 읽는 문제와 그 우회 명령.

**경로 1 — 인용 전수 대조.** 계획서의 `파일:줄` 인용 11건을 내용까지 대조. **불일치 0.**

**경로 9 — 구조적 아티팩트 검사.** 스키마 사본에서 컬럼·주석 4줄을 제거해

**경로 4 — 전칭 여집합 열거.** 여기서 소득이 둘 나왔다(아래).

### 라운드 1 소득 — 내 계획서의 결함 2건

둘 다 **경로 4가 잡았다.** 내가 쓴 문서인데 내 라운드가 잡았다는 점에서, 저자=검증자 구조에서도
기계적 경로는 값을 한다는 실측이다.

1. **전칭 열거가 불완전했다.** 계획서가 "`select` 없는 쿼리가 **다섯**"이라 하고 괄호로 둘만
   제외 설명했는데(`:44` `select` 있음, `:22` `createMany`), `clipDraft.*` 호출부를 전수로 세면
   **여덟**이다. 내가 설명하지 않은 여덟 번째가 `:117`
   `    const aggregate = await tx.clipDraft.aggregate({`다. 확인해 보니 `:119`
   `      _max: { index: true },`만 읽는 집계라 스칼라 행을 돌려주지 않아 **안전하다** — 결론은
   같지만 **근거가 비어 있었다.** 여집합 셋을 전부 적도록 고쳤다.
2. **주석 둘이 삭제될 컬럼을 가리킨다.** `packages/db/prisma/schema.prisma:60`
   `    // ClipDraft.captionStyle과 같은 CaptionStyle 모양이다.`(`User.defaultCaptionStyle`의
   설명)와 `apps/web/src/fsd/shared/config/caption-style-schema.ts:7-8`(「세 컬럼이 같은
   `CaptionStyle` 모양을 공유」)이다. **이건 내가 FEAT-52 인수에서 지적했던 것과 똑같은 부류다**
   (`constants.ts:113`이 삭제될 `RenderCaptionStyle`을 가리키던 건). 내 계획서가 같은 실수를
   반복했다. 전자는 내 범위라 「고칠 파일」에 넣었고, 후자는 `apps/web`(web-dev 몫)이라
   **FEAT-56에 관측 6으로 추가**했다 — 그 항목이 이미 같은 성격의 잔여 문구를 들고 있다.
   순서 제약(FEAT-53 뒤에 완전히 거짓이 된다)도 함께 적었다.

### 이 계획서의 핵심 — 적용 순서가 FEAT-47과 **반대**다

기록해 둘 값어치가 있다. FEAT-47(컬럼 **추가**)은 「적용 → 확인 → 커밋·푸시」로 **컬럼이 코드보다
먼저**여야 했다. **삭제는 반대다** — 지금 프로덕션에 떠 있는 클라이언트가 `captionStyle`을
SELECT하므로(위 다섯 쿼리), DB에서 먼저 지우면 검토 화면·편집 저장·렌더 디스패치·업로드 상세가
그 순간 `column does not exist`로 깨진다.

올바른 순서는 **커밋·푸시 → 새 클라이언트 배포 → `migrate deploy`**이고, 그 사이 상태(DB에는
컬럼이 있고 코드는 안 읽음)가 안전한 중간 지점이다. 반대 순서에는 안전한 중간 지점이 없다.
**FEAT-47의 순서를 습관적으로 따르면 장애**라서 계획서 앞쪽에 절로 박고 「대안 (C)」로도 기각해
뒀다.

## 라운드 2 (메인 루프, 무편집) — 2026-09-17

라운드 1의 편집이 준비도를 초기화하므로 무편집 재대조를 돌렸다. 계획서 인용 재대조 **불일치 0**,
내가 새로 주입한 인용 다섯(`schema.prisma:60` · `caption-style-schema.ts:7` ·
`clip-draft/api:117`·`:119`·`:22`)도 내용까지 일치. before 블록 BYTE-MATCH 유지.

**라운드 2 소득 0 — 무편집 무소득.** 판정이 아니라 디스패치 자격이다. `plan-verifier`에 독립
무편집 패스를 요청한다. 브리핑은 계약대로 셋만 보낸다(항목ID·계획서 경로·필수 경로 목록).

**이 항목에서 독립 패스는 평소보다 무겁다** — 계획서 저자가 나이므로, 내 라운드가 못 본 것을
볼 컨텍스트가 그것뿐이다.

## 독립 패스 1차 (`plan-verifier`) — 2026-09-17 · **결함 2건**

브리핑 계약은 온전했다(항목ID·계획서 경로·필수 경로 목록, 셋뿐). 검증자가 필수 6경로를 전부
실행했고 **내 계획서에서 결함 둘을 잡았다.** 둘 다 내가 직접 재대조했고 **둘 다 사실이었다.**

**결함 1 — 「깨지는 쿼리 다섯」이 틀렸다. 넷이다.** 내가 `:124`
`    return tx.clipDraft.create({`(`createCustomClipDraft`)를 "스칼라 전부 SELECT" 쪽에 넣었는데,
그 호출은 `:135` `      select: { id: true },`를 갖는다(내가 재독 확인). Prisma가
`INSERT … RETURNING id`로 컴파일하므로 이 컬럼을 참조하지 않는다.

**이건 내 문서가 자기 기준과 모순이었다** — 같은 문단이 `:44` findFirst를 "`select`를 갖는다"는
이유로 여집합에 넣고 있었다. 같은 기준이면 `:124`도 여집합이다. 그리고 검증자가 든 방증이
날카롭다: **내 「적용 순서」 절의 위험 문장이 나열하는 표면이 처음부터 넷**(검토 화면·편집 저장·
렌더 디스패치·업로드 상세)이고 커스텀 클립 생성은 거기 없었다. 문서 안에 반증이 이미 있었다.

임팩트는 검증자가 정확히 달았다 — **구현 산출물은 바뀌지 않는다**(schema 편집 + 마이그레이션 +
클라이언트 재생, `apps/web` 0줄). 안전 순서 결론도 깨지는 쿼리가 넷 남아 그대로 유효하다.
다만 **배포 후 검증 대상 목록**이 위험한 적 없던 쿼리를 포함하게 된다. 그래서 「못 덮는 범위」의
그 줄도 함께 고쳤다.

**결함 2 — 「apps/web에 주석이 하나 남는다」가 틀렸다. 둘이다.** 내가 지목한
`caption-style-schema.ts:7` 외에 `widgets/clip-draft-review/model/use-clip-draft-review.ts:128`
`                  // captionStyle은 의도적으로 낙관 반영하지 않는다. 헤더 카운트와`가 있다 —
낙관 업데이트가 `draft`(= `ClipDraft`)의 그 필드를 왜 안 건드리는지 설명하는 주석이다.

**다만 검증자가 우려한 결과는 일어나지 않는다** — 그 줄은 **이미 FEAT-56 관측 2가 들고 있다**
(「낡은 주석 3곳」의 하나로 `:128`·`:206`·`:216`을 인용). 내 문장이 여집합을 놓친 것이지 항목이
비어 있는 건 아니다. 그 사실까지 계획서에 적어 다음 사람이 중복 등재하지 않게 했다.

### 이 두 결함의 공통점

**둘 다 전칭이고, 둘 다 「하나/다섯」처럼 수를 세는 문장이었다.** 내 라운드 1도 같은 부류를
하나 잡았다(「다섯 쿼리」의 여집합이 비어 있던 것 — 그때 `aggregate`를 보강했다). **같은 문단을
세 번 고쳤다는 뜻이다.** 저자=검증자 구조에서 수를 세는 문장이 특히 약하다는 실측으로 남긴다.
